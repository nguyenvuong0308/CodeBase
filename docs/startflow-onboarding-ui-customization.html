02

Cung cấp nội dung từng trang

Sửa implementation mẫu AppOnBoardingContentProvider. Provider này dùng chung cho cả V1, V2 và V3.

✓
Kết quả: StartFlow lấy đúng ảnh/title/subtitle theo vị trí và biết tổng số content page.
AppOnBoardingContentProvider.kt
@Singleton
class AppOnBoardingContentProvider @Inject constructor()
    : OnBoardingContentProvider {

    override val introPageCount: Int = 3

    override fun getImageResIntro(position: Int): Int = when (position) {
        0 -> R.drawable.onboarding_01
        1 -> R.drawable.onboarding_02
        else -> R.drawable.onboarding_03
    }

    override fun getStringIntro(position: Int): Int = when (position) {
        0 -> R.string.onboarding_title_1
        1 -> R.string.onboarding_title_2
        else -> R.string.onboarding_title_3
    }

    override fun getSubtitleIntro(position: Int): Int? = when (position) {
        0 -> R.string.onboarding_subtitle_1
        1 -> R.string.onboarding_subtitle_2
        2 -> R.string.onboarding_subtitle_3
        else -> null
    }
}
Subtitle có điều kiện: V2 và V3 ở kiểu card top_v2 có dùng subtitle. Trả về null nếu muốn ẩn. Hãy đăng ký đúng một ContentProvider vì thứ tự phần tử trong Hilt Set không đảm bảo.

File mẫu có sẵn tại app/.../startflow/AppOnBoardingContentProvider.kt.

class AppOnBoardingV1UiCustomizer @Inject constructor()

        context: Context,
        state: OnBoardingV1PageState,
        current: OnBoardingV1UiSpec,

        actionText = context.getString(
            if (state.isLastPage) R.string.onboarding_start
            else R.string.onboarding_next
        ),
        actionTextColor = ContextCompat.getColor(context, R.color.onboarding_primary),
        actionBackgroundRes = R.drawable.bg_onboarding_action,

Đồng bộ Remote Config

Version quyết định customizer nào chạy; mảng intro_data* quyết định page content nào có quảng cáo.

✓
Kết quả: version, số content page, vị trí CTA và cấu hình ads khớp với code app.
Remote Config — ví dụ V3
{
  "onboarding_config": {
    "version": 3,
    "position_next": "bottom",
    "is_show_close": true,
    "is_show_swipe": true,
    "delay_show_close_swipe_seconds": 1
  },
  "application_config": {
    "intro_data_v3": [0, 1, 0]

}

0 • Content thường

Hiển thị page onboarding, không có banner/native ad.

1 • Content + ad

Hiển thị content page và vùng banner/native tương ứng.

2 • Full native

Đây là ad page, không tiêu thụ một vị trí content provider.

Điểm dễ nhầm ở V3: introductionPosition là vị trí logic có tính full-native ad; realPosition mới là vị trí content dùng để lấy ảnh và text.

Chạy app và kiểm tra

Kiểm tra theo thứ tự để phân biệt lỗi resource, Hilt và Remote Config. Đừng chỉ nhìn trang đầu tiên.

✓
Kết quả: cả trang thường, trang cuối và page có ads đều hiển thị đúng; navigation/tracking không bị phá vỡ.
  1. Clean/build app và xác nhận Hilt compile.
  2. Reset trạng thái đã xem onboarding trên máy test.
  3. Mở từng page, kiểm tra ảnh/title/subtitle.
  4. Kiểm tra CTA “Tiếp tục” và “Bắt đầu”.
  5. Thử swipe, close và delay theo config.
  6. Thử page có mã 1 và full-native 2.
  7. Xoay màn hình/background app nếu flow hỗ trợ.
  8. Xác nhận event view/next/complete vẫn được gửi.
PowerShell — kiểm tra module
.\gradlew.bat :core:startflow:test

Nếu cần theo dõi giá trị thực tế, log tạm state.pageType, state.realPosition, state.isPageEnd trong customizer rồi xóa log sau khi xác nhận.

Nâng cao: thay toàn bộ page UI

Dùng PageRenderer khi UiSpec không đủ. App inflate layout riêng, còn StartFlow vẫn sở hữu actions, lifecycle, navigation và tracking.

SpecialOnBoardingV3Renderer.kt
@Singleton
class SpecialOnBoardingV3Renderer @Inject constructor()
    : OnBoardingV3PageRenderer {

    override val priority: Int = 100

    override fun supports(state: OnBoardingV3PageState): Boolean =
        state.pageType == OnBoardingV3PageType.STANDARD

    override fun render(scope: OnBoardingV3RenderScope): OnBoardingV3RenderedPage {
        val binding = AppOnboardingSpecialBinding.inflate(
            scope.inflater, scope.parent, false
        )
        binding.image.setImageResource(scope.state.imageRes)
        binding.title.text = scope.state.title
        binding.subtitle.text = scope.state.subtitle
        binding.action.setOnClickListener { scope.actions.onPrimaryAction() }

        return OnBoardingV3RenderedPage(
            view = binding.root,
            onBannerNativeResult = { resource, placeName ->
                binding.layoutBannerNative.processAdResource(resource, placeName)
            },
            onDispose = { /* hủy animation/listener riêng */ },
        )
    }
}
  • Inflate với attachToParent = false.
  • Dùng scope.lifecycleOwner cho observer.
  • Gọi actions của scope, không tự navigate.
  • V3 phải forward callback ads vào ad container.
  • Dọn animation/listener trong onDispose.
  • Bind renderer bằng @IntoSet.
Không override XML core bằng resource trùng tên. View Binding của core yêu cầu đúng toàn bộ ID/type và có thể crash ngay lúc inflate.
!

Lỗi thường gặp

Mở từng mục để chẩn đoán nhanh trước khi sửa sâu vào core.

Code customizer không chạy
Kiểm tra onboarding_config.version, annotation @IntoSet, kiểu trả về của provider Hilt và việc app có đang bỏ qua onboarding do trạng thái đã xem hay không.
CTA drawable riêng không xuất hiện ở V2
Đặt isActionFillGradientEnabled = false. Gradient của view mặc định có thể đang phủ drawable bạn đã gán.
Ảnh/text bị lệch sau một full-native ad ở V3
Dùng realPosition cho content. introductionPosition là vị trí logic trong toàn bộ flow và có tính cả slot full-native.
Trang cuối hoặc text “Bắt đầu” bị sai
Đảm bảo introPageCount và mảng intro_data* khớp nhau. Với V1/V2 dùng isLastPage; với V3 dùng isPageEnd.
Renderer crash với “View must return without a parent”
Inflate binding bằng scope.inflater, truyền scope.parent nhưng tham số cuối phải là false. Không tái sử dụng view đã attach.
Kết quả style không như priority mong đợi
UiCustomizer chạy từ priority thấp đến cao; kết quả sau có thể override kết quả trước. Renderer thì chọn phần tử hỗ trợ page có priority cao nhất.

Hoàn tất khi 4 lớp đã khớp

Resources đủ theo position · Provider/Customizer trả đúng dữ liệu · Hilt bind đúng contract · Remote Config chọn đúng version và danh sách page.
